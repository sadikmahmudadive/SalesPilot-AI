# Phase 5c — Courier Integrations Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Automated shipping and parcel booking for Steadfast, Pathao, RedX, and Mock couriers, with normalized delivery statuses, automatic stock commit on pickup, idempotent webhook sync, address-to-area mapping cache, staff booking UI in order detail, and tracking data in AI customer responses.

**Architecture:**
- Courier accounts stored with encrypted credentials and webhook secrets (`secret-box.ts`).
- Standardized `CourierAdapter` interface for all logistics providers.
- Pathao OAuth2 token caching with single-flight refresh.
- Safe parcel booking state machine (`booking` lock, `booked`, `booking_unknown`, `failed`) that prevents duplicate parcels.
- Status normalization mapping raw courier statuses to standard `CourierStatus` and synchronizing order lifecycle (`shipped`, `delivered`, `returned`).
- Idempotent webhook receiver with secret validation, signature verification, and deduplication.

**Tech Stack:** Next.js 16 App Router, TypeScript strict, Zod 4, Firebase Admin + emulators, Vitest, TanStack Query, shadcn/ui.

**Spec:** `docs/superpowers/specs/2026-11-11-orders-payments-courier-design.md` (§3.4, §3.8, §7, §8, §9, §10, §11, §12).

### Task 5: Shipment Booking Service (Concurrency Guarded)

**Files:**
- Create: `src/services/couriers/booking.ts`, `src/services/couriers/booking.int.test.ts`
- Create: `src/app/api/orders/[id]/shipment/book/route.ts`, `src/app/api/orders/[id]/shipment/book/route.int.test.ts`

**Details:**
- `bookShipment(ctx, orderId, courierAccountId, options)`:
  - Step 1: Firestore transaction checks order is `confirmed` (COD) or `processing` (online must be `paid`). Acquires `bookingState: "booking"` lock with `bookingLockAt: now`.
  - Step 2: Outside transaction: if previous state was `booking_unknown`, tries `findParcelByInvoice` to adopt existing parcel; otherwise calls adapter `createParcel`.
  - Step 3: Firestore transaction records `bookingState: "booked"`, `consignmentId`, `trackingCode`, writes `orderEvents` and audit. On timeout / 5xx sets `booking_unknown` so retries won't double-book.

### Task 6: Inbound Courier Webhooks & Status Synchronization

**Files:**
- Create: `src/services/couriers/webhooks.ts`, `src/services/couriers/webhooks.int.test.ts`
- Create: `src/app/api/webhooks/couriers/[provider]/[accountId]/route.ts`, `src/app/api/webhooks/couriers/[provider]/[accountId]/route.int.test.ts`
- Create: `src/app/api/orders/[id]/shipment/refresh/route.ts`, `src/app/api/orders/[id]/shipment/refresh/route.int.test.ts`

**Details:**
- Route `POST /api/webhooks/couriers/[provider]/[accountId]`:
  - Validates account and verifies webhook signature with account secret.
  - Answers Pathao challenge handshake.
  - Dedupes via `webhookEvents`.
  - In a Firestore transaction: updates `shipment.status` if event is newer than current `statusAt`.
  - Triggers order lifecycle transitions:
    - `picked_up` / `in_transit` -> transitions order to `shipped` and commits stock.
    - `delivered` / `partial_delivered` -> transitions order to `delivered` (and marks COD collected).
    - `returned` -> transitions order to `returned`.
- Route `POST /api/orders/[id]/shipment/refresh`: calls adapter `getStatus` manually.
